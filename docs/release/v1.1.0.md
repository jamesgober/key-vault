# v1.1.0 — Dump Exclusion, Page Protection, Per-Key Lockout and no_std

**Release date:** 2026-10-09
**Phase:** 1.1.0 (minor release)
**Status:** **stable.** The 1.0 contract in [`docs/STABILITY-1.0.md`](../STABILITY-1.0.md) holds; everything here is additive.

---

## Why this release exists

1.0.2 made the documentation honest and listed what was still missing.
1.1.0 closes every item on that list that does not need a breaking
change: key memory is kept out of crash and core dumps, page protection
(Layer 10) exists, lockout can be per key, master unlock can be rate
limited, the vault's fragmenter can be chosen, the reserved Cargo
features now mean something (or are marked deprecated), the crate builds
without `std`, and the keychain and file fetchers are fixed. Existing
code builds and behaves the same unless it opts in.

---

## What's in 1.1.0

### Key memory stays out of crash and core dumps

Every page that holds key material is excluded from dumps:
`madvise(MADV_DONTDUMP)` on Linux and Android, `MADV_NOCORE` on FreeBSD
and DragonFly, `WerRegisterExcludedMemoryBlock` on Windows 10 1709 and
later (looked up at run time). This covers fragments, layout maps, codex
tables, the `with_key` scratch buffer, the normalization key and the
master verifier. macOS has no per-page equivalent, and dumps taken by a
debugger or another tool are not affected.

Small key buffers (up to 2048 bytes) now come from a pool of pages the
crate maps for itself, each locked and excluded once and holding only
key buffers. Registering and dropping keys makes no system calls once
the pool has grown, and unrelated heap objects no longer share key
pages. Larger buffers keep using the per-page reference count from
1.0.2.

### Page protection (Layer 10), opt-in

```rust
let vault = KeyVaultBuilder::new().with_page_protection(true).build();
```

Each registered key moves into a private mapping (at least one page)
that is `PROT_NONE` / `PAGE_NOACCESS` except while `with_key` reads it.
Concurrent readers share one open window. Cost: about 1.4-1.6 µs per
`with_key` on Linux. On Windows, `PAGE_NOACCESS` drops the page lock, so
protected keys can be paged out while inaccessible; keep the page file
encrypted if you turn this on there. Readers that go through the kernel
or a debugger are not stopped by it.

### Per-key lockout and master-unlock backoff, opt-in

```rust
let vault = KeyVaultBuilder::new()
    .with_key_lockout(5, Duration::from_secs(60), Some(Duration::from_secs(300)))
    .with_master_key(master)
    .with_master_unlock_backoff(Duration::from_secs(1), Duration::from_secs(60))
    .build();
```

Per-key lockout locks out only the key whose name crossed the threshold
(`is_key_locked_out`, `clear_key_lockout`). The backoff refuses master
attempts, unchecked, for `base`, `2 * base`, ... up to `max` after each
failure (`Error::RateLimited { retry_after }`). Breach events carry a
`LockoutScope`. Time comes from a `Clock`.

### Keyed hashing

The master verifier is now `BLAKE3-keyed(k, master)` with a random key
in locked memory, so a copy of the digest alone cannot be used to guess
the master. Normalization can be keyed too
(`with_keyed_normalization()`, `with_normalization_key(..)`); plain
BLAKE3 stays the default because the normalized value is the effective
key callers use, and changing it would change every key (planned for
2.0).

### Fragmenter selection and the Cargo features

`with_fragmenter` selects any `FragmentStrategy`, including your own
(`RawKey::expose_secret`, `Fragments::from_chunks` and the new
`Fragments` accessors make that possible). `LayeredFragmenter` no longer
copies every chunk on every read.

The 20 reserved features: `fragment-*`, `decoy-*`, `codex*`, `monitor`,
`audit` and the presets now choose what `KeyVaultBuilder::from_features()`
builds (`KeyVaultBuilder::new()` is unchanged); `mlock`, `zeroize`,
`tee-detect` and `post-quantum` are deprecated no-ops.

### `no_std` + `alloc`

`default-features = false` gives a `#![no_std]` crate. Build the vault
with `build_with_clock(your_clock)` (there is no `build()` without
`std`), and register a hardware RNG with `register_rng!` on targets
`getrandom` does not support; both are enforced at build time. Fetchers,
`monitor-tracing` and TEE detection need `std`. CI builds
`thumbv7em-none-eabihf`.

### Fixes

- **`KeychainFetch` never reached the OS keychain.** `keyring` was
  used without a store feature and fell back to its in-memory mock. The
  native stores are now enabled (Secret Service is pure Rust). New
  `KeychainFetch::binary()` reads binary secrets.
- **`FileFetch` checks the owner and the directories on the path** on
  Unix, and notices a path swapped after `open`.
  `skip_directory_check()` relaxes the directory check.

### Not in this release

These change behavior for existing users and wait for 2.0:

- Keyed normalization by default.
- Master-unlock backoff on by default.

TPM acquisition is still not implemented.

## Stability

- **Public API**: additions only. `cargo semver-checks` against 1.0.2:
  no breaking change (default and all features).
- **Feature names**: unchanged; four are now documented as deprecated.
- **MSRV**: unchanged, 1.85 (edition 2024).
- **Behavior**: unchanged unless you opt in, except for the fixes above
  (keychain store, `FileFetch` checks), dump exclusion, and the keyed
  master verifier (internal). Normalized key values are identical to
  1.0.2.

## Performance

Measured on Linux (WSL2, 4 pinned cores of a busy 32-core host),
1.0.2 and 1.1.0 benchmarked in alternating rounds; each number is the
best of three rounds. Absolute numbers on a quiet machine are lower;
compare the columns.

| Benchmark | 1.0.2 | 1.1.0 |
|-----------|-------|-------|
| `with_key/no_codex` 16 / 32 / 64 / 256 B | 34.6 / 42.0 / 56.5 / 167 ns | 33.9 / 41.2 / 55.4 / 157 ns |
| `with_key/with_codex` 32 / 256 B | 71.7 / 426 ns | 66.9 / 432 ns |
| `register/no_codex` 16 / 32 / 64 / 256 B | 5.4 / 18.6 / 39.8 / 99.8 µs | 1.0 / 2.2 / 4.0 / 16.2 µs |
| `rotate/no_codex` 16 / 32 B | 5.3 / 20.4 µs | 1.1 / 2.2 µs |
| `one_shot/defragment` 16 / 256 B | 37.5 / 189 ns | 39.2 / 192 ns |
| `vault_construction/default` | 119 ns | 119 ns |
| `concurrent_reads` 1 / 16 / 64 threads | 142 µs / 1.25 ms / 7.41 ms | 146 µs / 1.28 ms / 7.43 ms |
| `reads_during_rotation` (4 readers, 1 rotator) | 521 µs | 295 µs |

`register` and `rotate` are 4-8x faster because small key buffers come
from the page pool instead of locking and releasing heap pages one
system call at a time. `with_key` is unchanged within noise; the new
checks it makes when the options are off (per-key lockout, page
protection) are one atomic load and one branch.

Opt-in costs (1.1.0, same machine):

| Benchmark | 32 B | 256 B |
|-----------|------|-------|
| `with_key` with page protection | 1.42 µs | 1.58 µs |
| `register` with page protection | 9.0 µs | 24.5 µs |
| `with_key` with `LayeredFragmenter` | 49 ns | 163 ns |
| `register` with keyed normalization | 2.2 µs | — |

Page protection costs two `mprotect` calls per `with_key` and one
`mmap` + `mlock` + `madvise` + `mprotect` per registered key.
`LayeredFragmenter` used to copy every chunk into a new locked buffer on
each read; it now reads the chunks in place.

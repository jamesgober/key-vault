# v1.0.2 — Honest Threat Model, Page-Lock Refcounting and Registry Races

**Release date:** 2026-10-08
**Phase:** 1.0.2 (patch release)
**Status:** **stable.** The 1.0 contract in [`docs/STABILITY-1.0.md`](../STABILITY-1.0.md) is unchanged.

---

## Why this release exists

1.0.2 corrects documentation that overstated what the crate protects
against, fixes page locks being released while other keys still used
the page, wipes more buffers that hold key-derived bytes, and fixes two
races between registry writers. There are no public API changes;
`cargo semver-checks` against 1.0.1 reports no semver update required.

---

## What's in 1.0.2

### Security: the docs now say what each layer really does

README, `docs/SECURITY.md`, `docs/API.md`, `docs/TRANSFORMATION.md`,
the crate docs and the `Cargo.toml` feature comments have been
rewritten to match the code. The main corrections:

- **Fragmentation, decoys and the codex are obfuscation.** The layout
  buffer that reassembles the fragments (and marks every decoy chunk
  with `u32::MAX`) and the codex table live in the same process memory
  as the fragments. Anyone who can read the process's memory (a
  debugger, a same-user process with `ptrace` / `ReadProcessMemory`, a
  core dump, the kernel) can rebuild every key. These layers only raise
  the effort for generic scans and heap-dump tools. The docs had listed
  them as defenses against process memory scrapers. There is now a
  "Threat model" section in README, `docs/SECURITY.md` and the crate
  docs.
- **Layer 10 (page protection toggling) is not implemented.** There is
  no `mprotect` / `VirtualProtect` call in the crate.
- **Decoys and the codex are off by default.** They apply only when
  set with `KeyVaultBuilder::with_decoy` / `with_codex`.
- **20 Cargo features gate no code.** `mlock`, `zeroize`, `codex`,
  `codex-dynamic`, all `decoy-*`, all `fragment-*`, `monitor`, `audit`,
  `tee-detect`, `post-quantum` and all `preset-*` are documented as
  reserved, no effect in 1.0.x. They are kept because removing a
  feature is a breaking change.
- **`FileFetch` reads a plaintext file**; it was described as
  encrypted file storage. **`TpmFetch` is not implemented**; it was
  listed as the highest-security, hardware-backed fetcher.
- **Lockout is advisory and vault-wide.** It counts only failures the
  caller reports, and one key name crossing the threshold locks out
  every key. `unlock_with_master` has no rate limit. Normalization and
  the master digest are unsalted, fast BLAKE3.
- Constant-time claims are limited to the master digest check and
  handle equality; TEE detection is documented as heuristic.

### Security: page locks are reference counted

`mlock` / `VirtualLock` lock whole pages and do not nest: one unlock
releases the page however many buffers on it were locked. Fragments
are small separate allocations, so fragments of different keys share
pages. In 1.0.1 dropping any fragment (on `rotate`, `unregister`, a
one-shot `defragment`, or a dropped codex) unlocked its whole page
range, and other live keys on those pages silently lost their lock.

1.0.2 keeps a process-wide per-page reference count. A page is locked
when the first buffer on it is created and unlocked only when the last
one is dropped. On Linux, registering 200 pairs of keys and then
unregistering one key of each pair took `VmLck` from 276 kB to 0 kB in
1.0.1; in 1.0.2 it stays where it was. The `with_key` scratch buffer is
now locked through the same table.

Tests: two regions on one page (release one, the count stays at 1);
two vault keys sharing a page (unregister one, the other's pages stay
counted and readable); a Linux `VmLck` check in
`tests/mlock_verified.rs` that fails against 1.0.1.

### Security: more key-derived buffers are wiped

The `zeroize` crate is now a required dependency (the `zeroize` feature
remains and has no effect), and `blake3` is required at `>= 1.5` with
its `zeroize` feature. Newly wiped:

- `RawKey`'s whole allocation, including spare capacity. Before, only
  `0..len` was cleared.
- BLAKE3 hasher state and output readers in normalization, the master
  digest and `KeyDerivedDecoy`; digests go straight into zeroizing
  buffers.
- The master digest in `KeyVaultBuilder` (and its clones) and
  `KeyVault`, on drop.
- Decoy output, fragmenter temporaries and codex construction tables,
  on every exit path.
- `FileFetch` read buffers on error and on growth, the rejected value in
  `EnvFetch`'s non-UTF-8 path, and the bytes in `keyring`'s
  `BadEncoding` error.

Copies made inside `std`, the OS, `keyring` or the caller's `with_key`
callback are outside the crate's control; the docs list them.

### Fixed: registry write races

- **Duplicate names.** `register` checked for the name on one snapshot
  and inserted into a later one, so concurrent registrations of the
  same name could all succeed. In a new 8-thread x 200-round test,
  1.0.1 registered every name 8 times.
- **`rotate` vs `unregister`.** `rotate`'s `found` flag was not reset
  between `ArcSwap::rcu` retries, so if `unregister` won the race,
  `rotate` returned `Ok` and audited a rotation that was never stored.
  A new test parks `rotate` between its check and its update while
  `unregister` runs; 1.0.1 returned `Ok` in 10 of 10 rounds.

Registry writers are now serialized by a writer lock and re-check their
precondition under it. Reads (`with_key`, `contains`, `metadata`) stay
lock-free.

### Fixed: other

- `FileFetch` opens the file once and checks the permission bits on the
  open handle, so the check and the read see the same file. It used to
  call `metadata(path)` and then `read(path)`.
- `register` and `rotate` no longer emit an extra unnamed
  `OneShotFragment` audit event.
- `TpmFetch`'s error message no longer suggests
  `detect_tee_capabilities()` can find a TPM.
- `rustfmt` 1.99: lowercase hex literals in two files.

### Not in this release

These need an API addition or a behavior change and are planned for
1.1 or 2.0:

- Per-key lockout and a backoff on `unlock_with_master` (1.1).
- A builder option to choose the vault's fragmenter, and wiring or
  deprecating the reserved features (1.1).
- Opt-in page protection (Layer 10) and `MADV_DONTDUMP` / dump
  exclusion (1.1).
- A keyed or slow KDF for normalization and the master digest (2.0).

  222 checks pass, no semver update required (default and all
  features).
- **Feature names**: unchanged.

- **Behavior**: unchanged except for the fixes above. Normalized key
  values are identical to 1.0.1 (checked against `blake3::hash`).
